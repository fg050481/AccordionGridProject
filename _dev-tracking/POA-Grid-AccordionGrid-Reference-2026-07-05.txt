SERVER-SIDE MODE (dataLoader) — the production configuration

    filter. _apply() calls dataLoader(params, done) with:
        { page, pageSize, search, filter, sortKey, sortDir }

  ✔ updateRecord / removeRecord skip the dataLoader re-fetch and re-render

  ✔ Scales to 10,000+ records — bottleneck is the SQL Skip/Take query, not JS.
  ✔ Initial page 1 delivered via HiddenGridData hidden field (+ 
    window.poaInitialData fallback); every later interaction hits GetPage.

───────────────────────────────────────────────────────────────────────────────
 PART 2 — THE KEY CONTRACT (read this before adding any field)
───────────────────────────────────────────────────────────────────────────────

The entire data binding is ONE line:

    var val = record[field.key];

The key string is matched EXACTLY, with no compiler check, in FOUR places.
All four must agree or the failure is silent:

  1. The server flattener (GetPage projection) — defines the wire name
  2. editFields  { key: '...' }                — binds the input
  3. editSections fields: ['...']              — places it in a section
  4. onSave DTO builder  e.record.XXX          — sends it back

NAMING CONVENTION (all lookup/FK fields):
    <Name>      = display string   e.g.  ServiceType   = "ADP - UCM"
    <Name>Id    = numeric FK       e.g.  ServiceTypeId = 8

RULES:
  • type:'select' fields MUST key on the numeric  <Name>Id  property.
    The dropdown option values are ints; record[key] must be an int too,
    or no <option> matches and the browser silently shows the FIRST option.
  • Never key a select on the display string. It will LOOK correct in view
    mode (the fallback echoes the raw string) and be WRONG in edit mode.
  • text / textarea / checkbox / date fields key on their single property
    directly (Description, Notes, Active…) — no string/id split exists.
  • Renaming a key = renaming it in ALL FOUR places in the same change.

SILENT FAILURE MODES (what you see when one place is missed):
  ┌────────────────────────────┬──────────────────────────────────────────┐
  │ Missed place               │ Symptom                                  │
  ├────────────────────────────┼──────────────────────────────────────────┤
  │ editFields only            │ edit dropdowns default to first option   │
  │ editSections not updated   │ field vanishes from its section (falls   │
  │                            │ into unlabeled leftover block at bottom) │
  │ onSave not updated         │ form looks perfect, server receives null │
  │                            │ (parseInt(undefined) → NaN → || null)    │
  │ flattener emits other name │ record[key] undefined → blank view "—",  │
  │                            │ edit shows first option                  │
  └────────────────────────────┴──────────────────────────────────────────┘

 PART 3 — FIELD CONFIGURATION EXAMPLES (copy-paste patterns)
───────────────────────────────────────────────────────────────────────────────

3a. TEXT (required, with placeholder)
    { key: 'Description', label: 'Description', type: 'text',
      required: true, placeholder: 'Enter description' }

3b. SELECT bound to a lookup (THE standard FK pattern)
    // record must carry  ServiceTypeId: 8  (int) from the flattener
    // LOOKUPS.serviceTypes = [ { value: 1, label: 'Full Service' }, ... ]
    { key: 'ServiceTypeId', label: 'Service Type', type: 'select',
      options: LOOKUPS.serviceTypes }

3c. SELECT with a STRING value (State — the one legit exception)
    // Here value IS the string code, matching record.State = "TX"
    // LOOKUPS.states = [ { value: 'AL', label: 'AL' }, ... ]
    { key: 'State', label: 'State', type: 'select',
      options: LOOKUPS.states }

3d. CHECKBOX
    { key: 'Active', label: 'Active', type: 'checkbox' }
    // NOTE: input returns true / 'true' / 'on' — coerce in onSave:
    //   Active: e.record.Active === true || e.record.Active === 'true'
    //           || e.record.Active === 'on'

3e. READ-ONLY text (written by the upload widget, not the user)
    { key: 'FileName',          label: 'File Name',          type: 'text', readOnly: true },
    { key: 'DocumentReference', label: 'Document Reference', type: 'text', readOnly: true }
    // readOnly (not disabled!) — disabled inputs are excluded from
    // _collectFormValues and their values would be lost on save.

3f. TEXTAREA spanning the full row width
    { key: 'Notes', label: 'Notes', type: 'textarea',
      fullWidth: true, placeholder: 'Optional notes…' }

3g. DATE / NUMBER / EMAIL
    { key: 'EffectiveDate', label: 'Effective Date', type: 'date' }
    { key: 'MaxPages',      label: 'Max Pages',      type: 'number' }
    { key: 'ContactEmail',  label: 'Contact Email',  type: 'email' }

3h. CUSTOM render (full control over the field's HTML)
    { key: 'Score', label: 'Score', type: 'custom',
      render: function (field, record) {
          return '<div class="my-score">' + (record.Score || 0) + ' / 100</div>';
      } }

3i. onChange hook (react to a field edit live)
    { key: 'ReturnTypeId', label: 'Return Type', type: 'select',
      options: LOOKUPS.returnTypes,
      onChange: function (key, value, record) {
          console.log(key + ' changed to ' + value + ' on row ' + record.Id);
      } }


───────────────────────────────────────────────────────────────────────────────
 PART 4 — SECTIONS EXAMPLE (green header groupings)
───────────────────────────────────────────────────────────────────────────────

Every string in fields:[] must EXACTLY match an editFields key.
A non-matching string is silently skipped.

    var editSections = [
        { title: 'Template Info',
          fields: ['Description', 'State', 'MailCenterId', 'Active'] },

        { title: 'Classification',
          fields: ['ServiceTypeId', 'FormTypeId', 'FormUseId', 'PoaTypeId'] },

        { title: 'Processing Rules',
          fields: ['SignatureTypeId', 'ReturnTypeId', 'OnlineRequirementId'] },

        // isDocumentSection: true → the PDF upload widget is injected here
        { title: 'Document',
          fields: ['FileName', 'DocumentReference'], isDocumentSection: true },

        { title: 'Notes', fields: ['Notes'] }
    ];

Fields defined in editFields but listed in NO section render in an unlabeled
remainder block at the bottom of the panel (this is also where a typo'd
section entry "sends" a field — check there first when one goes missing).


───────────────────────────────────────────────────────────────────────────────
 PART 5 — COLUMNS EXAMPLE (collapsed row display)
───────────────────────────────────────────────────────────────────────────────

    var columns = [
        // plain sortable text
        { key: 'Description', label: 'Description', sortable: true },

        // fixed width, centered
        { key: 'State', label: 'State', width: '70px',
          sortable: true, align: 'center' },

        // badge column: value → css class map
        { key: 'ExtractionStatus', label: 'Extraction', width: '130px',
          sortable: true,
          badge: { map: { 'Completed': 'success', 'In Progress': 'info',
                          'Not Started': 'default', 'Error': 'danger' },
                   defaultClass: 'default' } },

        // custom format function (return HTML string)
        { key: 'Active', label: 'Active', width: '70px', align: 'center',
          format: function (v) {
              return v ? '<span class="ag-badge ag-badge-success">Yes</span>'
                       : '<span class="ag-badge ag-badge-danger">No</span>';
          } }
    ];

NOTE: column keys can use the display-string properties (State,
ExtractionStatus…) — columns just print, they never need to match option
values. The Id-suffix rule applies to SELECT editFields only.

 PART 6 — ACTION BUTTONS EXAMPLE
───────────────────────────────────────────────────────────────────────────────

    var actionButtons = [
        { key: 'edit',    label: 'Edit' },
        { key: 'extract', label: 'Extract' },

        // conditional visibility per record
        { key: 'generate', label: 'Generate', cssClass: 'ag-btn-primary',
          visible: function (r) { return r.MappingStatus === 'Mapped'; } },

        { key: 'download', label: 'Download',
          visible: function (r) {
              return !!(r.DocumentReference && r.DocumentReference.length > 0);
          } },

        { key: 'delete', label: 'Delete', cssClass: 'ag-btn-danger' }
    ];

    // Clicks arrive in ONE place — route by e.action:
    onActionClick: function (e) {
        switch (e.action) {
            case 'edit':   grid.expandRowForEdit(e.id); break;
            case 'delete': /* confirm → DeleteForm → grid.removeRecord */ break;
            // e.id = internal _agId · e.record = full record object
        }
    }

 PART 8 — ADD-A-NEW-FIELD CHECKLIST (the 4-place walk)
───────────────────────────────────────────────────────────────────────────────

Adding e.g. a "Priority" lookup field:

  □ 1. SERVER: add to lookups (LoadLookups → LOOKUPS.priorities) and to the
       GetPage flattener:   Priority = x.Priority, PriorityId = x.PriorityId
  □ 2. editFields:
       { key: 'PriorityId', label: 'Priority', type: 'select',
         options: LOOKUPS.priorities }
  □ 3. editSections: add 'PriorityId' to the target section's fields array
  □ 4. onSave DTO:  PriorityId: parseInt(e.record.PriorityId, 10) || null
       + add int? PriorityId to PoaFormDto + map to entity column on server
  □ 5. TEST: arrow-expand (label shows) → Edit (pre-selects) → change + Save
       → Network tab body has the int, not null → reopen row → persisted
